# Agent testing with MySQL Workbench

Use a test copy of the client's database containing an active country. The schema dump alone does not include real geography, vehicle or rate data.

1. Connect Workbench to the test DB and double-click the intended schema. Open `sql/create-test-agent.workbench.sql` in the Node folder and execute the ENTIRE file. It uses only existing users, agencies, agents, customers and agent-assignment tables. No CREATE/ALTER or migrations. The final row must say READY and returns the real user_id, agency_id, agent_id and booking_customer_id.
2. Default test login: `agent.qa@driveluxury.test`; password `DriveLuxury-QA-2026!`. POST `/api/v1/auth/login` with `{"email":"agent.qa@driveluxury.test","password":"DriveLuxury-QA-2026!"}`. Use the returned accessToken with Authorization: Bearer on GET `/api/v1/agent/dashboard` and `/api/v1/agent/profile`.
3. The script uses role 4, users.status=0 (active), agencies.status=1 (active), and agents.agent_type=2 (agency member). Do not accidentally set users.status=1. It does not grant admin rights, disable 2FA, or edit someone else's account.
4. Repeat execution reuses the same test identity without resetting its password. A name/email collision or missing active country returns STOP and performs no inserts. Change the identity using the generator rather than overwriting a real user's password. Node command to regenerate: set TEST_AGENT_EMAIL and TEST_AGENT_PASSWORD in your shell, then run `npm run agent:test-sql`. Generation itself never connects to a DB. If customizing the password, use that password in the login request; the SQL contains a Laravel-compatible bcrypt hash, not plaintext.
5. The script creates/reuses `client.qa@driveluxury.test`, links its native customer row to the QA agency, and assigns it to the test agent. Use the returned `booking_customer_id` as `customerId` in POST `/api/v1/bookings/drafts`. The QA agency commission is 10%, so commission behavior is visible in dashboard testing. For additional clients, use POST `/api/v1/agent/clients`; an admin can use POST `/operations/agent-client-assignments` for an existing client. A customer belonging to another agency must not be linked.
6. Choose an actual configured service/class/country/season/rate before quoting or checking out. A successful draft creation does not manufacture fleet or pricing data. Use the same test inputs as the website. Complete a mock booking only with PAYMENT_PROVIDER=mock on your test backend. For Stripe staging use test keys and signed test webhooks.

Do not run this fixed public test credential on production. No live test account was created by this package. To remove it, prefer DELETE /auth/account while logged in as this test agent with confirm=true and the test password. Native financial history and the shared agency are retained under soft deletion. Regenerating SQL does not reactivate a deleted account.
